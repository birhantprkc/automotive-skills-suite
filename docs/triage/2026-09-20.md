## 1. The recurring "needs human triage" finding is structural, not an oversight

Four consecutive Sundays (08-09, 08-16, 08-23, 09-06) flagged issues with a domain label
but no type label and declined to guess. Counting across the repo's full history explains why.

| Measure | Count |
|---|---|
| Issues ever opened (excl. PRs) | 51 |
| Issues with **no** type label | **26 (51%)** |
| Of those, `weekly-target` PLAN issues | **26 (100%)** |

Every single untyped issue is a PLAN-generated one. The cause is the PLAN issue template,
which emits `labels: ["weekly-target", "<domain>"]` and no type. And no type in the mandated
seven — `skill-bug`, `reviewer-finding`, `description-quality`, `new-skill`, `docs`, `ci`,
`chain-break` — describes "polish this builder"; they are all defect or content-category
labels. A polish target is a *work item*, not a finding.

So triage is being asked each week to classify issues into a taxonomy that has no bucket for
them, and the ≥80%-confidence rule correctly refuses every time. It will keep refusing forever
unless the taxonomy changes. **This is a human decision and I did not make it.** The two
coherent options:

- **(a)** add a `polish` type label and have PLAN emit it — one label, one template line; or
- **(b)** declare `weekly-target` self-typing and exempt it from the type requirement — zero
  new labels, one rule change in the triage step.

Either closes the finding permanently. Doing neither means logging it a fifth, sixth, seventh time.
